# Подготовка pull request

Применяй при подготовке описания и создании PR в PureAndroid. Заголовок и описание пиши на английском.

## Содержание

- Заголовок кратко описывает результат изменения. Для префикса области можно использовать принятую в коммитах форму `[main]`, `[database]`, `[test]` или другую подходящую область.
- Начни описание с решённой проблемы и нового поведения. Для небольшого изменения достаточно одного-двух предложений и результатов проверки.
- Если есть связанная задача, добавь её реальную ссылку в Markdown.
- Укажи выполненные проверки и их результаты. Для отложенных проверок укажи причину и необходимые команды. При изменении UI добавь доступные скриншоты, если они помогают оценить изменение.
- Запуск Gradle и тестов регулируют [правила проекта](code-quality.md). Для обновления зависимостей также примени [правило обновлений](dependency-upgrades.md).

Основа описания, которую нужно заполнить по фактическому diff и проверкам.

```markdown
## Summary

<Problem addressed and resulting behavior.>

## Validation

<Checks performed and their results, plus any pending checks and reasons.>
```

## Создание через GitHub CLI

1. Проверь `gh --version` и `gh auth status --hostname github.com`. Продолжай через CLI после успешного выполнения обеих команд.
2. Проверь репозиторий, текущую ветку, её коммиты и полный diff относительно целевой ветки. Для PureAndroid целевая ветка по умолчанию — `main`, на неё настроен [CI](../.github/workflows/ci-pull-request.yml). Учитывай явно указанную пользователем целевую ветку.
3. Проверь публикацию ветки и наличие уже открытого PR для неё. При повторной работе обнови существующий PR.
4. Получи список доступных labels через `gh label list --repo DeveloperPalmer/PureAndroid --limit 1000`. Если список достиг лимита, увеличь лимит, чтобы увидеть все метки. Выбирай метки по их реальному названию и описанию, области изменений и типу работы. Добавь все явно подходящие метки, включая метку AI-помощи, если такая существует и применима. Если подходящих меток нет, отметь это в итоговом сообщении. Ошибку получения списка сообщи как ограничение проверки меток.
5. Сохрани готовое описание в UTF-8 во временный файл и передай его через `--body-file`. Для каждой выбранной метки добавь `--label '<точное имя>'`. Назначь текущего GitHub-пользователя через `--assignee '@me'`.

Пример команды для PowerShell с заполнителями для ветки, заголовка и файла описания.

```powershell
gh pr create --repo DeveloperPalmer/PureAndroid --base main --head '<branch>' --title '<title>' --body-file '<absolute-path-to-body.md>' --assignee '@me'
```

После создания проверь заголовок, описание, ветки, assignee и labels у полученного PR и верни его ссылку. Результаты CI сообщай по фактическому статусу проверок.

## Ручное создание

Если автоматическое создание недоступно, подготовь готовые заголовок и описание и дай ссылку сравнения опубликованной ветки. Для PureAndroid используй адрес вида `https://github.com/DeveloperPalmer/PureAndroid/compare/main...<branch>?expand=1`, заменив ветки фактическими значениями и закодировав специальные символы для URL. Укажи необходимые assignee и labels, если удалось получить их список.

Синтаксис команд описан в документации [gh pr create](https://cli.github.com/manual/gh_pr_create) и [gh label list](https://cli.github.com/manual/gh_label_list).
