# Android: архитектура и контракты

## Orbit и жизненный цикл

Основа — [BaseViewModel](../../../../core/ui/src/main/kotlin/ru/sla/pure/android/core/ui/mvi/BaseViewModel.kt). Проверяй каждое действие пользователя и событие экрана: метод ViewModel должен обрабатывать его в `intent { ... }`, изменять состояние через `reduce { state.copy(...) }`. Редьюсер не должен выполнять побочные действия. Начальное состояние должно корректно отображаться; loading допустим, если это состояние предусмотрено сценарием.

Проверяй переходы успех/ошибка/повтор/отмена, защиту от повторных запросов и результат устаревшей операции. Одноразовый эффект не должен превращаться в повторяемое состояние или теряться без учёта подписки экрана. Не выдавай наружу изменяемые потоки состояния.

Контейнер Orbit связан с ViewModel. Видимость экрана, наличие записи в стеке и очистка ViewModel — разные события. Модели флоу живут в scope компонента, который отменяет [FlowComponentViewModel](../../../../core/routing/src/main/kotlin/ru/sla/pure/android/core/routing/FlowComponentViewModel.kt) в `onCleared()`. Проверяй владельца и отмену работы, особенно при выходе из аккаунта и смене корня.

## Metro и модули

- Проверяй `@Inject`, `@ContributesBinding`, `@ContributesIntoMap`, `@ViewModelKey`, assisted-фабрики и квалификаторы относительно фактического графа. Не считай все ошибки DI исключительно runtime-проблемами: часть обнаруживает генерация/компиляция.
- `@Provides` и `@Binds` размещай в отдельном модуле соответствующего компонента, как требует AGENTS.md. Экземпляры, передаваемые при создании графа, остаются параметрами фабрики.
- Scope и `@ForScope` должны соответствовать владельцу: приложение, флоу или запись экрана. Проверяй удержание Activity, пересоздание зависимостей и совместное использование состояния разных экранов.
- Domain — Kotlin/JVM без data/ui зависимостей. Data реализует domain-интерфейсы и использует инфраструктуру данных. UI получает модель через ViewModel. Routing связывает data/domain/ui; прямые зависимости разрешаются фактической ролью модуля и [конвенциями](../../code-quality/SKILL.md), а не запретом всех межфичевых ссылок.
- Не редактируй сгенерированные исходники; исправляй определения графа, API или схемы.

## Compose и Navigation 3

- Экран принимает ViewModel и данные; callback действий, событий и навигации в параметрах экрана запрещён. Внутренний компонент может делегировать callback методу ViewModel.
- Навигация проходит через `FlowEventSink`; решение принимает routing. Проверь путь события до обработчика, регистрацию Route/EntryProvider и соответствие аргументов assisted-фабрике.
- [NavigationState](../../../../app/routing/src/main/kotlin/ru/sla/pure/android/app/routing/NavigationState.kt) содержит отдельные стеки вкладок, сохранение ключей и декораторы `ViewModelStore`/saveable state. Проверь Back, predictive back, переключение вкладок, восстановление и удаление записей. Разные детали не должны случайно разделять одну ViewModel.
- Выход из аккаунта должен согласованно завершать сессию, очищать предусмотренные данные и заменять корень навигации; ошибка не должна оставлять UI в вечной блокировке.
- Для размеров, insets, ресурсов и темы используй [правила Compose UI](../../compose-ui-review/SKILL.md). Не объявляй визуальное совпадение по исходникам без рендера.

## Сеть и ошибки

Проверь [NetworkModule](../../../../app/data/src/main/kotlin/ru/sla/pure/android/app/data/di/NetworkModule.kt), `ServerJson`, `ApiErrorCallAdapterFactory`, `NetworkErrorConverter` и соответствующие API/мапперы. Сохраняй различие HTTP-ошибки, ошибки формата, отсутствия сети, таймаута и отмены; не превращай `CancellationException` в ошибку UI или успешный ответ.

Учитывай срок жизни клиента, timeouts, закрытие вручную читаемых response bodies, проверку входных идентификаторов, nullability и контракт сериализации. Не требуй оборачивать каждый suspend Retrofit-вызов в `Dispatchers.IO`; найди реально блокирующую операцию и её поток.

В `MainRepositoryImpl` кэш используется при `ConnectivityError`; проверь, что изменение не скрывает иные ошибки и сохраняет порядок страниц/элементов. Для Remo проверь обработку success/errors, стратегию очереди и scope задачи. Не навязывай `kotlin-result` там, где проект использует исключения и типы ошибок domain.
