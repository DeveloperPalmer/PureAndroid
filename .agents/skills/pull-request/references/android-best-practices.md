# Android: проверки реализации

- Состояние должно быть неизменяемым для потребителя. Для реально разделяемого `MutableStateFlow` проверь атомарность read-modify-write; для Orbit используй его `reduce`, не параллельное хранилище состояния.
- `remember`, `derivedStateOf`, ключи эффектов и стабильность типов оценивай по зависимостям и времени жизни. Проверь устаревшие захваченные значения, повторные эффекты и очистку `DisposableEffect`. `@Stable`/`@Immutable` — обещание контракта; ошибочная аннотация также может скрывать обновления.
- Сохраняй семантику, доступность и используемые тестами `testTag`. Не требуй новый тег у каждого элемента без потребителя.
- У каждой корутины должен быть владелец. Проверь работу после ухода со страницы и после удаления флоу; `GlobalScope` или отдельный scope требует обоснованного времени жизни и освобождения ресурсов.
- Проверяй dispatcher по коду: `createCoroutineScope()` моделей использует Default, ViewModel может задавать Main.immediate. Блокирующие I/O и тяжёлые вычисления не должны блокировать UI. Не переносись на Main/IO только по имени функции.
- Ошибки должны доходить до нужного обработчика; `SupervisorJob` не заменяет обработку исключения. Сохраняй отмену, освобождай ресурсы и слушателей. Сравнивай вложенные collect с требуемым поведением combine/merge, а не заменяй их автоматически.
- Для `SharedFlow` проверяй replay, подписчиков, `emit`/`tryEmit`, буфер и результат отправки. Нулевая ёмкость сама по себе не доказывает потерю события. Текущий `FlowEventSink` вызывает обработчик синхронно — не приписывай ему буфер SharedFlow.
- Проверяй Activity/Context, удерживаемые объектами более долгого scope, а также реальные сигналы LeakCanary. Для приложения/БД используй application context там, где не нужен Activity.
- Не записывай токены, пароли и персональные данные в логи. В PureAndroid есть `Log.d` и `printStackTrace`; не требуй отсутствующий Timber. Оцени содержимое, окружение и последствия логирования.
- Проверяй доступность API на поддерживаемых SDK, правила R8 для реально используемой рефлексии/сериализации и debug/release-различия. Версии и настройки бери из текущих Gradle-файлов.
