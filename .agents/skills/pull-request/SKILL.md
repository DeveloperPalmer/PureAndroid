# Pull request и ревью PureAndroid

Применяй при подготовке, создании, обновлении и ревью PR, а также при ревью локальных изменений. Это самостоятельный skill с адаптацией правил omim, выполняемый текущим агентом. Для него не нужны сервис Karandash, корпоративные токены или CI-интеграция.

## Подготовка и публикация PR

Для описания, заголовка, коммитов, labels, assignee и публикации прочитай [правила подготовки PR](references/pr-preparation.md). При обновлении существующего PR используй полный итоговый diff. Запрос подготовки описания сам по себе не разрешает публикацию.

## Ревью

1. Прочитай [контекст проекта](references/extra-instructions.md) и [процедуру ревью](references/review-prompt.md).
2. Установи базовую ревизию, текущий HEAD и состав изменений. Для PR используй его фактическую целевую ветку; для локальных изменений учитывай явно заданные пользователем staged/unstaged/committed границы. Не смешивай чужие изменения с предметом ревью.
3. Выбери владельцев затронутого поведения по [карте проекта](../navigation-map/SKILL.md). Прочитай только применимые разделы:
   - Kotlin/Java, Compose, ресурсы, навигация, DI, сеть и общий Kotlin-код: [Android](references/android-instructions.md) и [практики Android](references/android-best-practices.md).
   - `database/`, Room-сущности, DAO, конвертеры, схемы, настройка БД и потребители хранения: [база данных](references/database-instructions.md).
   - `.github/workflows/`, Gradle-файлы, `build-conventions/`, Wrapper и конфигурация анализа: [CI и сборка](references/ci-instructions.md). Обновления версий дополнительно проверяй по [правилу зависимостей](../dependency-upgrades/SKILL.md).
   - Сравнение UI с макетом: [Compose UI](../compose-ui-review/SKILL.md).
4. Проследи последствия diff в вызывающем коде и потребителях. Общие изменения проверяй во всех затронутых фичах, а не только в изменённом модуле.
5. Оформи подтверждённые замечания по [формату ревью](../review-comment-format/SKILL.md). Сначала дефекты по серьёзности, затем выполненные проверки, непроверенные сценарии и вопросы. Проверку оформления PR отделяй от дефектов кода и выполняй по [правилам PR](references/pr-preparation.md).

Ревью само по себе не разрешает исправления, коммиты, push, публикацию комментариев или закрытие обсуждений. Выполняй эти действия при соответствующей просьбе. Gradle, IDE-синхронизацию, сборки и тесты запускай только по явной просьбе на операцию; новые тесты добавляй только по явной просьбе. Анализ исходников не выдавай за результат сборки или проверки на устройстве.

Источник адаптации — предоставленные документы omim: `.karandash/instructions/extra-instructions.md`, `.karandash/prompts/review-prompt.md` и Android/CI/database scopes. Здесь используется стек PureAndroid. Наследуемая удалённая конфигурация omim не изучена и не является скрытым набором требований этого skill. Не расширяй правила догадками о ней.
