# Инструкции для PureAndroid

## Перенос инструкций

- Адаптируй переносимые документы под фактический код, инструменты и соглашения PureAndroid, сохраняя смысл требований. Если для требования отсутствует участок кода, инструмент, правило или другое необходимое основание, спроси разработчика, как с ним поступить, прежде чем удалять, ослаблять или заменять это требование. Продолжай независимые части адаптации, пока ожидаешь ответ.

## Ориентация в коде

- Для поиска нужного модуля, экрана, маршрута, DI-привязки или теста используй [карту проекта](docs/navigation-map.md).

## Pull requests

- Для явно запрошенного полного цикла небольшого исправления используй скилл [quick-fix](.agents/skills/quick-fix/SKILL.md). Он принимает GitHub Issue или описание в чате, оформляет коммиты по практике проекта и сохраняет отдельное согласование запуска Gradle.
- При подготовке или создании pull request применяй [правила оформления PR](docs/pull-request-template.md).
- При ревью кода и подготовке комментариев к PR применяй [формат замечаний ревью](docs/review-comment-format.md).

## Gradle

- При изменении Gradle-конфигурации сверяйся с [правилами проекта](docs/code-quality.md) и файлами затронутых модулей.
- При обновлении или ревью обновления зависимостей, Android SDK, BOM, плагинов, Gradle Wrapper или JDK прочитай и примени [правило обновления зависимостей](docs/dependency-upgrades.md).
- Запускай Gradle, включая отчёты о зависимостях, синхронизацию, сборки, форматирование, анализ и тесты, только по явной просьбе выполнить соответствующую операцию. Это касается также IDE, скриптов и других агентов. В остальных случаях изучи файлы и diff, укажи команды для разработчика и отметь, какие результаты требуют проверки.

## Compose UI

- Composable-функции экранов принимают ViewModel и данные для отображения. Запрещено передавать в параметры экрана callback для обработки действий пользователя, событий экрана или навигации.
- Каждое действие пользователя и событие экрана передавай методу ViewModel, который обрабатывает его внутри Orbit `intent { ... }`. Если событие требует навигации или действия на уровне флоу, ViewModel отправляет `FlowEvent` через `FlowEventSink`, а решение принимает модуль routing.
- Внутренние UI-компоненты могут принимать обработчики, которые делегируют действие соответствующему методу ViewModel.

- Для отступов используй `VSpacer`, `HSpacer` и `WSpacer` из `ru.sla.pure.android.uikit.spacer`. При сравнении экрана с макетом применяй [чек-лист Compose UI](docs/compose-ui-review.md).
- Источник Figma пока открыт. При каждом новом запросе с упоминанием Figma, пока подходящая ссылка отсутствует, напомни об этом и предложи варианты «A — добавить ссылку» и «B — пропустить». Пропуск относится к текущей задаче. Подробности и параметры сравнения заданы в чек-листе.
- Для доступа к Studio используй [Android CLI](docs/android-studio-cli.md).
